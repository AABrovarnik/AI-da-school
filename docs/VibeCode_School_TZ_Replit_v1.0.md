# Техническое задание v1.0 — AI-da-school / VibeCode School для Replit

## 1. Общая информация

**Название проекта:** AI-da-school / VibeCode School  
**Формат:** web-школа вайбкодинга для детей 10–14 лет  
**Руководитель школы:** Броварник Александр Алексеевич  
**Платформа разработки и запуска:** Replit  
**Основной инструмент разработки:** Replit Agent + Project Editor  
**Дата старта первого потока:** 10 октября 2026 года  
**Продолжительность:** 10–12 недель  
**Язык интерфейса:** русский  
**Учебные уровни:** VibeCode START и VibeCode PRO

## 2. Цель проекта

Создать на Replit полнофункциональную web-школу, в которой дети учатся создавать сайты, игры и AI-приложения в формате vibe coding.

Основной учебный цикл:

**Идея → постановка задачи → промпт → генерация → запуск → тестирование → ошибка → исправление → улучшение → публикация.**

AI-наставник должен помогать ребёнку понимать задачу, находить ошибки и улучшать проект, но не выполнять учебную работу полностью вместо ученика.

## 3. Подход к разработке в Replit

Проект должен разрабатываться в Replit с использованием следующего процесса:

1. Импортировать существующий GitHub-репозиторий `AABrovarnik/AI-da-school` в Replit.
2. Использовать Replit Agent в режиме Plan для анализа ТЗ и построения плана реализации.
3. После утверждения плана выполнять разработку по этапам.
4. Каждую крупную функцию проверять в Preview.
5. После стабильной работы публиковать приложение через Replit Publishing.
6. Все секреты хранить в Replit Secrets.
7. Постоянные пользовательские данные хранить в SQL Database, а не в локальной файловой системе опубликованного приложения.

## 4. Требования к технологическому стеку

### Frontend
- React;
- TypeScript;
- Vite;
- React Router;
- адаптивный интерфейс;
- desktop-first для программирования;
- корректная работа на планшете и телефоне для просмотра уроков и общения с AI.

### Backend
- Node.js;
- Express;
- REST API;
- server-side вызовы Gemini API;
- централизованная обработка ошибок;
- логирование ошибок без записи чувствительных пользовательских данных.

### Database
Использовать Replit SQL Database / PostgreSQL.

Подключение получать из переменной окружения:

`DATABASE_URL`

Для ORM допустимо использовать Drizzle ORM или Prisma. Предпочтительно Drizzle как лёгкий вариант для MVP.

### AI
- Gemini API;
- API key хранить только в Replit Secrets;
- переменная: `GEMINI_API_KEY`;
- frontend не должен получать ключ;
- AI-запросы идут только через backend endpoint.

## 23. Child Safety и Privacy by Design

Основные требования:

- собирать только минимально необходимые данные;
- не требовать домашний адрес;
- не требовать точную дату рождения без необходимости;
- не просить телефон ребёнка;
- не просить пароли или платёжные данные в AI-чате;
- AI не должен предлагать личное общение вне платформы;
- системный prompt хранить server-side;
- защитить AI endpoint от prompt injection;
- ограничить размер запроса;
- добавить rate limiting;
- логировать технические ошибки без содержимого чувствительных сообщений.

Перед коммерческим использованием необходим отдельный юридический аудит обработки данных несовершеннолетних.

## 29. Replit Publishing

Для первой рабочей серверной версии использовать deployment, поддерживающий Node.js backend, предпочтительно Autoscale.

Перед публикацией проверить:
- backend доступен;
- production environment variables заданы;
- база данных подключена;
- frontend корректно обращается к backend;
- API key не попадает в browser bundle;
- refresh маршрутов работает;
- данные сохраняются после перезапуска;
- мобильная версия не ломается.

## 30. Workflow разработки в Replit Agent

Перед изменениями Agent должен:

1. Прочитать ТЗ и файлы `dev-package/`.
2. В Plan mode составить план.
3. Показать:
   - архитектуру;
   - страницы;
   - data model;
   - этапы;
   - критерии готовности;
   - риски.
4. После подтверждения реализовать MVP по этапам.
5. После каждого этапа запускать приложение в Preview.
6. Исправлять ошибки до перехода дальше.
7. Использовать checkpoints перед крупными архитектурными изменениями.

## 31. Acceptance Criteria

MVP считается готовым, если:

### Ученик
может открыть сайт, выбрать курс, открыть урок, выполнить задание, сохранить прогресс, создать проект, сохранить новую версию проекта, обратиться к AI-наставнику и вернуться к своим данным после повторного открытия приложения.

### AI-наставник
учитывает уровень и урок, объясняет ошибки, использует постепенные подсказки и не выдаёт без необходимости полное решение.

### Администратор
может управлять учебными данными без переписывания frontend.

### Replit
приложение работает в Preview и в Published deployment; секреты находятся в Secrets; постоянные данные хранятся в SQL Database.
